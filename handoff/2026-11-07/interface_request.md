**背景**：计划 §3.3 只定了主键与必备字段名，没定列名、精度与空值规则。11/11 20:00 你交 `accessibility`、我 11/12 20:00 交两张表，中间只有 24 小时——**字段对不上就没有返工余地**，所以提前把格式钉死。

## 一、请求的表结构

一行一个 `(zone_id, d0)`；三套半径就是三倍行数。

| 列名 | 类型 | 含义 | 备注 |
|---|---|---|---|
| `zone_id` | str | 需求单元 ID（TAZ 或 1 km 格网） | 与 `zone_master` 同键 |
| `d0` | int | 服务半径（km）：3 / 1 / 5 | 三套都要 |
| `a_i` | float | 可达性，**桩/人**（未乘 1000） | 保留 6 位小数 |
| `a_i_per_1k` | float | 每千人桩数 = `a_i × 1000` | 你也可以只给 `a_i`，我这边换算 |
| `has_station` | bool | 该 `d0` 内是否有**观测**公共站点 | M3 判定「无观测覆盖」直接用它 |
| `border_flag` | bool | 边界单元（被市界或样本边界裁切） | 报告里要单列并集里边界单元的占比 |
| `pop` | float | 人口（人） | 从 `zone_master` join 过来，表头注明 2020 年七普 |

```csv
zone_id,d0,a_i,a_i_per_1k,has_station,border_flag,pop
TAZ001,3,0.004312,4.312,true,false,8213
TAZ002,3,0.000000,0.000,false,false,1502
```

---

## 二、四条硬要求

1. **三套半径齐全。** 缺 1 km 或 5 km，M5 的半径敏感性直接做不了，而它是「实验设计 35%」的证据之一。
2. **`has_station` 必须按各自的 `d0` 分别算。** 3 km 没站不等于 5 km 没站；这个布尔值一变，受影响人口就变。
3. **样本外单元不要出现在表里，也不要用 0 补齐。** 未观测区域赋零供给违反 §2.3 口径二。表里的 0 只能表示「有人在、但可达性算出来是 0」。
4. **精度别砍到两位小数。** Gini 对尾数敏感，`0.004312` 砍成 `0.00` 会让低可达单元全部并列，阈值判定直接失真。
